# Compliance checklist

R15's legal checklist, per `runs/R15-hardening.md`'s "Legal checklist" build item: walk every row of
`docs/legal-requirements.md` and mark each as covered by a named test or missing. Generated by reading
`docs/legal-requirements.md` in full, then opening the actual `describe`/`it` blocks under `test/` (not
guessing from filenames) and reading the source each test exercises in `src/`. the build notes were used
only to write an accurate one-line implementation note next to a row, the Status and Evidence columns come
from tests actually opened and read, listed by file and name. Sections below mirror
`docs/legal-requirements.md`'s own structure.

## Unexplained gaps

These are the rows above marked Missing or Partially covered where the shortfall is not already accounted
for by an open question, a stated CONFIRM item, or a progress-note explanation, genuine follow-ups worth a
decision before go-live. R15 closed four of the six gaps this checklist originally found (audit logging on
ceiling alerts and the crossing block, the ITA connection check after the switch, the amendment-37 test,
and the CeilingCrossingDialog test); R16 closed the remaining two (the per-client ledger now rides in the
accountant pack, task 11; the quarterly backup now also copies to Google Drive, task 12; see

Two additional Missing/Partial rows are explained and not listed above as genuine gaps: the day-10/14-day
tax-invoice task (explicitly stubbed and reasoned about in the R11 build notes, and largely
moot given the system's actual same-step payment-to-invoice flow), and the periodic VAT report/PCN874 duty

explicitly). The buyer-side input-VAT check is similarly explained as a named, tracked follow-up
(the build notes, R07 and R11/R12 sections) rather than a silent omission, though it remains real,
unfinished work.

### A new gap this run's own e2e testing surfaced

Writing `test/e2e/murshe-allocation-and-refusal.test.ts` against the real documents/ita modules
together (rather than the synthetic, directly-inserted document rows `test/ita/allocation.test.ts`
uses) found that refusal choice 3, reverse charge, does not actually work end to end today:
`D1AllocationDocuments.createReverseChargeReplacement` (`src/modules/ita/documents.ts`) still
throws `reverse_charge_unavailable` unconditionally. This was already a named follow-up in
the build notes ("Build the reverse-charge replacement builder and wire it into
`D1AllocationDocuments.createReverseChargeReplacement`"), so it counts as explained, not
unexplained, but it is worth flagging here explicitly since it means one of the four legally
required refusal choices (docs/israel-invoices-api.md section 6, choice 3) is not actually usable
in production yet, only in the service-level tests that swap in the in-memory fake store. The new
e2e test pins today's real 409 behavior so a future fix shows up as an intentional test change.
